# Ux Laws

Pick the principle(s) that match the decision at hand, read only those reference files, then apply them:

1. Name the principle and the concrete UI element it constrains.
2. State the expected user effect (speed, error rate, recall, perceived grouping…).
3. Propose the change, and flag any principle it trades off against.

| Principle | What it says |
|---|---|
| [fitts law](references/fitts-law.md) | Apply Fitts's Law — target acquisition time depends on size and distance |
| [hicks law](references/hicks-law.md) | Apply Hick's Law — decision time grows with the number of simultaneous choices |
| [jakobs law](references/jakobs-law.md) | Apply Jakob's Law — users expect your product to work like the others they already use |
| [millers law](references/millers-law.md) | Apply Miller's Law — chunk information into groups of about four to fit working memory |
| [teslers law](references/teslers-law.md) | Apply Tesler's Law — every process has irreducible complexity that someone must absorb |
| [doherty threshold](references/doherty-threshold.md) | Apply the Doherty Threshold — keep system response under 400ms to preserve user flow |
| [peak end rule](references/peak-end-rule.md) | Apply the Peak-End Rule — a flow is remembered by its most intense moment and its last |
| [serial position effect](references/serial-position-effect.md) | Apply the Serial Position Effect — first and last items in a sequence are recalled best |
| [von restorff effect](references/von-restorff-effect.md) | Apply the Von Restorff Effect — the element that differs from its neighbours is the one remembered |
| [zeigarnik effect](references/zeigarnik-effect.md) | Apply the Zeigarnik Effect — incomplete tasks stay mentally active |
| [aesthetic usability](references/aesthetic-usability.md) | Apply the Aesthetic-Usability Effect — polished, consistent interfaces are perceived as more usable and forgive minor friction |
