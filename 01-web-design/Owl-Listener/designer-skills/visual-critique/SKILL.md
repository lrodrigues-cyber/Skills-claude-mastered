# Visual Critique

Pick the principle(s) that match the decision at hand, read only those reference files, then apply them:

1. Name the principle and the concrete UI element it constrains.
2. State the expected user effect (speed, error rate, recall, perceived grouping…).
3. Propose the change, and flag any principle it trades off against.

| Principle | What it says |
|---|---|
| [critique affordance](references/critique-affordance.md) | Critique a rendered screen's affordances — what looks clickable, state visibility, CTA clarity, and action discoverability |
| [critique brand consistency](references/critique-brand-consistency.md) | Critique a rendered screen against mood.md, voice.md, and tokens.md |
| [critique color](references/critique-color.md) | Critique a rendered screen's colour — contrast ratios, palette coherence, and semantic meaning |
| [critique composition](references/critique-composition.md) | Critique a rendered screen's composition — balance, whitespace, rhythm, and gestalt grouping |

| [critique visual hierarchy](references/critique-visual-hierarchy.md) | Critique a rendered screen's hierarchy — entry point, eye flow, weight distribution, and emphasis |
